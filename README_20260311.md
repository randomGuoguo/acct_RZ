# acct_RZ README 2026-03-11

`acct_RZ` 是一个基于 `Polars` 的违约历史特征与查询项目。

截至 2026-03-11，项目主产品已经切换为：

- `blacklist_features.parquet`

`step1~step4` 仍然保留，但只作为兼容输出。

## 1. 主产品

主产品文件：

- `data/result/blacklist_features.parquet`

主产品粒度：

- 每个查询键一行

主键列：

- `app_dt`
- `key_type`
- `key_value`
- `PID`
- `ID`

当前主产品已包含的特征族：

- lifetime history
- rolling windows
- stable org_type breakdown
- stable perf_type breakdown
- complexity features

当前主产品中的代表字段：

- `ever_default_flag`
- `first_default_dt`
- `latest_default_dt`
- `days_since_latest_default`
- `default_cnt_lifetime`
- `default_cnt_3m`
- `default_cnt_12m`
- `default_cnt_36m`
- `default_cnt_12m_bank`
- `default_cnt_12m_dpd`
- `is_multi_org_default_12m`

## 2. 第一版边界

第一版明确不做：

- `sample_flag` 展开进主宽表
- 高基数机构名级宽表展开
- channel 级宽表展开

第一版只展开稳定低基数维度：

- `org_type`: `bank`, `rate24`, `rate36`
- `perf_type`: `fpd`, `dpd`

## 3. 运行方式

### 3.1 Batch

默认命令：

```bash
conda run -n dl_new python run_pipeline.py
```

指定输入输出：

```bash
conda run -n dl_new python run_pipeline.py --input data/demo/y.csv --output data/result
```

Batch 默认输出：

- `blacklist_features.parquet`
- `step1_blacklist.parquet`
- `step2_traceback.parquet`
- `step3_org_blacklist.parquet`
- `step4_window_counts.parquet`

### 3.2 Query

命令示例：

```bash
conda run -n dl_new python run_pipeline.py --mode query --input data/demo/y.csv --query-input data/demo/query.csv --output data/result
```

Query 模式返回：

- `blacklist_features`
- `step1`
- `step2`
- `step3`
- `step4`

## 4. 当前架构摘要

当前主链路为：

```text
history_df/query_df
-> query_snapshot + event_fact
-> agg_* reusable aggregations
-> labels_* feature families
-> product_blacklist_features
-> blacklist_features.parquet
```

兼容链路为：

```text
blacklist internals
-> features_blacklist / features_org_blacklist / features_windows
-> step1~step4 compatibility outputs
```

## 6. 输入与输出契约

查询输入至少需要：

- `app_dt`
- 合法的 `PID` / `ID`

支持的 `app_dt` 格式：

- `YYYYMMDD`
- `YYYY-MM-DD`

支持的 `key_type`：

- `pid`
- `id`
- `pid_id`

最终对外日期列统一序列化为：

- `YYYYMMDD`
- `Int64`

## 8. 接手建议

如果要扩特征：

1. 优先看 `agg_*.py` 和 `labels_*.py`
2. 其次看 `product_blacklist_features.py`
3. 最后才考虑兼容层 `features_*.py`

如果要扩高基数维度：

1. 不要直接继续扩主宽表
2. 优先设计 detail 层产物

如果要理解当前架构：

1. 先看 `architecture_20260311.md`
2. 再看 `TSAK——20260311.md`
